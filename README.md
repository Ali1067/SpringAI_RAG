# Spring AI RAG Demo

A minimal Retrieval-Augmented Generation (RAG) sample built with **Spring Boot**, **Spring AI**, and **PostgreSQL/pgvector**.

The app embeds a small "help pages" knowledge base into a vector store, retrieves the most relevant entries for a user's question, and asks an LLM to answer **only** from that retrieved context — reducing hallucination and keeping returned URLs sourced from the database rather than generated by the model.

## How it works

1. On startup, `KnowledgeBaseLoader` reads rows from the `help_pages` table and loads them into the pgvector-backed `VectorStore` as embedded documents.
2. A client sends a question to `POST /api/ai/ask`.
3. `RagService` runs a similarity search (top 5, similarity threshold `0.45`) against the vector store to find relevant help pages.
4. The retrieved titles/URLs/descriptions are stitched into a prompt that instructs the LLM to answer only from that context.
5. The response includes the generated answer plus the source page(s) it was grounded in.

## Tech stack

- Java 17, Spring Boot 3.5
- Spring AI 1.0 (OpenAI chat/embedding models, pgvector vector store)
- PostgreSQL 17 with the `pgvector` extension
- Maven

## Prerequisites

- JDK 17+
- Maven 3.9+
- Docker (recommended) **or** a local PostgreSQL 17 instance with the `vector` extension available
- An OpenAI API key

## Guidelines: setting up the database

You can either let Docker Compose provision the database automatically, or set it up manually against an existing PostgreSQL instance.

### Option A — Docker Compose (recommended)

```powershell
docker compose up -d
```

This starts a `pgvector/pgvector:pg17` container, exposed on `localhost:5433`, and automatically:
- creates the `rag_demo` database (via `POSTGRES_DB=rag_demo`)
- runs `db/init.sql`, which enables the `vector` extension and creates/seeds the `help_pages` table

No manual database creation is needed with this option.

### Option B — Manual setup against an existing PostgreSQL server

If you're not using the provided Docker container, create the database and schema yourself:

```sql
-- 1. Create the database
CREATE DATABASE rag_demo;

-- 2. Connect to it, then enable pgvector and create the schema
\c rag_demo

CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE IF NOT EXISTS help_pages (
    id BIGSERIAL PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    url VARCHAR(500) NOT NULL,
    keywords TEXT,
    description TEXT NOT NULL
);
```

Then load the sample data from `db/init.sql` (or insert your own rows into `help_pages`):

```powershell
psql -h localhost -p 5432 -U postgres -d rag_demo -f db/init.sql
```

> The `vector` extension must be installed on the PostgreSQL server for `CREATE EXTENSION vector` to succeed (this ships by default in the `pgvector/pgvector` Docker image; on a self-managed server you may need to install the `pgvector` package first).

Update `src/main/resources/application.yml` with your database host/port/credentials if they differ from the defaults (`localhost:5433`, `postgres`/`postgres`).

## Running the app

1. Start the database (see Guidelines above): `docker compose up -d`
2. Set your OpenAI API key:
   ```powershell
   $env:OPENAI_API_KEY="YOUR_API_KEY"
   ```
3. Run the app:
   ```powershell
   mvn spring-boot:run
   ```
4. Import `postman/Spring-AI-RAG-Demo.postman_collection.json` into Postman, or call the API directly.

## Using the API

```
POST http://localhost:8080/api/ai/ask
Content-Type: application/json

{
  "question": "How do I submit a memo?"
}
```

Sample response:

```json
{
  "answer": "Use the Submit Memo page to create and submit a new memo.",
  "pageTitle": "Submit Memo",
  "url": "/cab-memo/submit",
  "sources": [
    { "title": "Submit Memo", "url": "/cab-memo/submit" }
  ]
}
```

Sample data is defined in `db/init.sql` — edit or extend `help_pages` to try your own content. URLs returned in the response always come from the database, never generated by the LLM.

## Notes

RAG greatly reduces hallucination but cannot mathematically guarantee zero hallucination; the prompt and application-controlled sources act as guardrails, not an absolute guarantee.
